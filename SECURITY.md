# Security policy

Browser Research Bridge is an experimental, read-only local preview. A dedicated low-privilege Chrome profile is mandatory. Do not use it with a profile containing unrelated personal, financial, administrative, or highly sensitive sessions.

## Supported boundary

The project helps an agent read rendered pages the configured Chrome profile is already authorized to view. It must not be extended to solve CAPTCHAs, evade bot detection, spoof browser identity, extract or replay credentials, defeat paywalls, or bypass authentication and authorization controls.

## Reporting

Do not publish a vulnerability that could allow a website or local process to control the extension, read arbitrary page content, or steal the bridge token. Report it privately to the repository owner first.

## Known prototype risks

- Broad Chrome host permissions.
- The Native Messaging host and extension are local development builds, not signed releases; authenticated loopback remains enabled as a fallback.
- The shared token is a 256-bit lowercase hexadecimal value generated by setup and never transmitted over loopback. A local process that independently obtains the token can still authenticate, so protect the configuration file and use a dedicated OS account for stronger local-process isolation.
- The broker resolves both the requested and final URL, and the extension re-reads the tab URL immediately before extraction. The extra Chrome DNS check is available only in Chrome Dev/Chrome for Testing because `chrome.dns` is not exposed by Stable Chrome. These checks prevent extraction after a policy failure, but are not an atomic network sandbox. DNS can change between validation and navigation, Chrome's API exposes only one answer, and Chrome may issue a redirect request before the final URL is available for inspection.
- In-memory rather than encrypted capture storage.
- No signed release or automatic update chain.
